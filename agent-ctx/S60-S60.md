# Sprint 60 — ANE Per-Op Constraints and CPU_ONLY Hard Gate

## Summary

Sprint 60 implements per-op constraint validation functions, dtype/format constraint validation, the CPU_ONLY hard gate op list, ANE memory layout/interleave types, and hardware limit enforcement.

## Files Created

### S60.1: Per-op constraint validation
- `crates/passes/src/op_constraints.rs` — Validation functions for conv, linear, gather, pooling, argminmax, and tensor rank constraints

### S60.2: Data type / format constraint validation
- `crates/passes/src/dtype_constraints.rs` — dtype legality per ANE family, quantization/dequantization format validation, broadcast dtype checks

### S60.3: CPU_ONLY hard gate
- `crates/passes/src/cpu_only_ops.rs` — 108-entry CPU_ONLY_OPS set with reason codes, `is_cpu_only()` and `get_cpu_only_reason()` functions
- `crates/passes/src/legality_rewrite.rs` — Modified `make_air_node()` to check CPU_ONLY before soft scoring (hard gate)

### S60.4: AneInterleave type and layout constraint validation
- `crates/ir/src/ane_layout.rs` — AneInterleave enum (1/2/3/4/8), AneLayout enum, validate_interleave_constraints(), validate_channellast_constraints()

### S60.5: Hardware limit enforcement
- `crates/ir/src/ane_hw_limits.rs` — AneHwLimits struct with per-revision parameters, validate_tensor_dims()
- `knowledge/cpu_only_ops_seed.json` — 108-entry JSON seed with op names and reason codes
- `knowledge/ane_hw_limits_seed.json` — Per-revision hardware limits as JSON

### Updated: AneFamily/AneRevision
- `crates/ir/src/ane_target.rs` — Added A15, A16 family variants, supports_sdpa(), supports_layernorm() methods (needed by Sprint 59's placement_validate.rs)

## Files Modified
- `crates/passes/src/lib.rs` — Added `pub mod cpu_only_ops; pub mod dtype_constraints; pub mod op_constraints;`
- `crates/ir/src/lib.rs` — Added `pub mod ane_hw_limits; pub mod ane_layout;`
- `crates/passes/src/legality_rewrite.rs` — Added CPU_ONLY hard gate in `make_air_node()`
